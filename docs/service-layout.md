# 支付宝业务包目录

本目录覆盖 `alipay.*` 的 678 个 V3 REST 操作。接口契约保持原样，按业务子域选择包并调用 `NewService(executor)`；不同 Service 可复用同一 `*core.Client`。页面产物与支付通知仍由 `services/trade` 提供。

专属请求、响应和模型随接口放入业务包；跨组模型保留在共同父包。父包不聚合或导入子包，各子包不依赖兄弟业务包。较小且职责单一的业务保留在原包。

使用默认编解码器的接口可直接调用 `core.ExecuteJSON[Req, Resp](ctx, executor, spec, request)`，统一完成 Operation 构造并委托 `core.Execute`。接口名、HTTP 方法、路由、参数模式及认证要求由业务包通过 `core.OperationSpec` 显式传入，调用设置通过 `core.Request` 传入；业务包无需重复定义执行辅助函数。需要复用 Operation 或自定义编解码器时，继续使用 `core.NewJSONOperation` / `core.NewOperation` 与 `core.Execute`。

新增接口优先复用现有业务包；当一个包混合多个独立业务前缀时再拆子包，不按 CRUD 动作逐个建包。请求、响应、模型或测试接近 500 行时按业务主题、类型或接口分文件；单个接口的完整示例独立存放，避免累积证书装载样板代码。API 契约变更仍须以官方文档为依据。

SDK 方法与配套类型按单词边界使用大驼峰命名，例如 `PreCreate`、`BatchQuery`、`OrderInfoSync`、`BillDownloadURLQuery`；常见缩写保留 `API`、`ID`、`URL`、`QRCode`、`OAuth` 的大小写。请求、响应、专属模型、枚举和示例使用相同词干。官方接口名、HTTP 路由、JSON 字段及包导入路径保持官方或既有形式。当前版本直接更正名称，不提供旧名称的兼容入口。

## 调用迁移示例

- 原 `fund.Service.UniTransfer` 改为导入 `services/fund/trans`，使用 `trans.NewService(client)` 和 `trans.UniTransferRequest`。
- 原 `data.Service.BillDownloadURLQuery` 改为导入 `services/data/bill`，使用 `bill.NewService(client)` 和 `bill.BillDownloadURLRequest`。
- 商户、用户、企业码、搜索等接口通过下表找到相应子包；方法名未作缩写或兼容转发。
